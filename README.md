# Mega Services Bot (Modular Architecture)

هذا المشروع عبارة عن بوت تيليغرام مصمم ليكون "بوت خدمات شامل". تم بناء الهيكل الأساسي (Architecture) ليكون **Modular** (مقسم إلى وحدات/إضافات مستقلة)، مما يعني أنه يمكنك إضافة مئات الخدمات والميزات في المستقبل دون أن يتداخل الكود أو يصبح معقداً.

## الهيكل التنظيمي للمشروع (Folder Structure)

يعتمد المشروع على الهيكل التالي:

```text
mega-bot/
├── index.js                 # نقطة الدخول الرئيسية (المحرك الذي يجمع كل شيء)
├── package.json             # ملف التبعيات والإعدادات
├── README.md                # هذا الملف
└── src/                     # مجلد الكود المصدري
    ├── core/                # الملفات الأساسية التي يعتمد عليها البوت
    │   └── config.js        # إعدادات البوت ومتغيرات البيئة
    ├── utils/               # أدوات مساعدة عامة يمكن استخدامها في أي موديول
    │   └── crypto.js        # أدوات التشفير (AES-256-GCM)
    └── modules/             # **هنا يتم إضافة الخدمات الجديدة**
        └── gps-tracker/     # الموديول الأول: خدمة تتبع الموقع
            ├── index.js     # كود الخدمة (الأوامر والمسارات)
            └── templates/   # ملفات HTML/CSS الخاصة بهذه الخدمة
                └── page.html
```

## كيف يعمل النظام الموديولي؟

ملف `index.js` الرئيسي مبرمج ليقوم بـ **قراءة مجلد `src/modules/` تلقائياً**.
عند تشغيل البوت، سيبحث في هذا المجلد عن أي مجلد فرعي يحتوي على ملف `index.js`، وسيقوم بتشغيله وتمرير كائن البوت (`bot`) وكائن السيرفر (`app`) إليه.

هذا يعني أنك **لست بحاجة لتعديل الملف الرئيسي `index.js`** عند إضافة خدمة جديدة!

## كيف تضيف خدمة جديدة (ميزة جديدة) مستقبلاً؟

لنفترض أنك تريد إضافة خدمة جديدة لتحميل الفيديوهات، كل ما عليك فعله هو:

1.  إنشاء مجلد جديد داخل `src/modules/`، مثلاً: `src/modules/video-downloader/`.
2.  إنشاء ملف `index.js` داخل هذا المجلد الجديد.
3.  كتابة كود الخدمة داخل هذا الملف بهذا الشكل الأساسي:

```javascript
// src/modules/video-downloader/index.js

module.exports = (bot, app) => {
    // إضافة أمر جديد للبوت
    bot.command('download', (ctx) => {
        ctx.reply("أرسل لي رابط الفيديو لتحميله.");
    });

    // يمكنك أيضاً إضافة مسارات ويب (API) خاصة بهذه الخدمة
    app.get('/api/download-status', (req, res) => {
        res.json({ status: "working" });
    });
};
```

بمجرد إعادة تشغيل البوت، سيتم التعرف على خدمة `video-downloader` تلقائياً وتفعيل أمر `/download`.

## النشر على Render

1.  ارفع مجلد `mega-bot` (أو محتوياته) إلى مستودع GitHub.
2.  في Render، أنشئ **Web Service** جديدة واربطها بالمستودع.
3.  إعدادات Render:
    *   **Build Command:** `npm install`
    *   **Start Command:** `node index.js`
4.  **متغيرات البيئة (Environment Variables) المطلوبة في Render:**
    *   `BOT_TOKEN`: توكن البوت الخاص بك (مثال: `8961277817:AAEFIB-p-3_QV3lbvC7_3bfyx68f5NfckVM`).
    *   `DOMAIN`: رابط تطبيقك على Render (مثال: `https://my-mega-bot.onrender.com`).
    *   `ENCRYPTION_KEY`: (اختياري ولكن موصى به) مفتاح تشفير سداسي عشري بطول 32 بايت. إذا لم تضعه، سيقوم النظام بتوليد واحد عشوائي في كل مرة يشتغل فيها السيرفر (مما يعني أن الروابط القديمة لن تعمل بعد إعادة تشغيل السيرفر).

## الموديول الحالي: تتبع الموقع (GPS Tracker)

هذا هو الموديول الأول المدمج في البوت.
*   **الأمر:** `/gpsid`
*   **الوظيفة:** يولد رابط مشفر (AES-256-GCM) يرسله المستخدم للهدف. عند فتح الرابط، يتم بث الموقع الحي للهدف إلى شات المستخدم.
*   **الأمان:** يتم تشفير `Chat ID` الخاص بالمستخدم، ولا يتم حفظه كنص صريح. الروابط تنتهي صلاحيتها بعد 24 ساعة.
